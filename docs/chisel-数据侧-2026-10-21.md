# `chisel` 数据侧（「吃成什么样」标签）—— 2026-10-21

## 目的

现在「吃成什么样」是**引擎的向听启发式**决定的 ✗ 模型从来没学过 ✗
`chi` 这个头只有 0/1（吃不吃）✓ 没有「用哪两张吃」✗
-> 新增一列 `chipat` + 一个新头，让模型自己学吃法 ✓

## 设计（为什么加一列，而不是改 `action`）

```
✗ 改 action：现有 8 列会变 ✗ 老数据被污染 ✗ 且和二值 chi 头冲突 ✗
✓ 加 chipat：**独立一列** ✓ 现有 8 列逐位不变 ✓ 老权重照用 ✓
```

## 编码（推理端必须用同一个 ✓ 否则训练/推理对不上 ✗）

```
chipat = -1   不是吃 / 该局没有合法吃法 / 人选择不吃
chipat = k    人实际用的是 sorted(合法吃法)[k]，k 从 0 起
合法吃法 = 「另外两张」的 (a,b)，按 (a,b) 升序 ✓
一张牌的合法吃法最多 3 种 ✓ -> 新头宽度 3 ✓
```

## 实现（4 处）

```
agents.py      Tracker.chipats + record(chipat=-1) + clear + arrays() 输出 int8 列 ✓
tenhou_bc.py   _legal_chi_pairs(hand, tile)  ✓ 按 (a,b) 升序，确定性 ✓
               decide() 里记下合法吃法 + 行号 ✓
               backfill_chi(ev) 在吃牌事件到达后回填序号 ✓
               dispatch() 里触发 ✓
```

## 🔴 踩到的坑（两个，都记下来）

```
① 丢弃不忠实的局时，截断了 8 个并行列表，**漏了 chipats** ✗
   症状：chipat 比 X 多 854 条、**非 chi 行也带 0/1**、填充率看着只有 8.5% ✗
   根因：`del lst[start_idx:]` 那个元组里没有 chipats ✗
   修法：加进去 ✓
   教训：**并行列表必须显式列全** ✗ 少一个就是静默错位 ✗

② 8.5% 这个数**差点被我当成 bug** ✗ —— 其实是对的 ✓
   chi 决策有 2,180 条，但人只**吃了 184 条** ✓（8.4% ✓ 吃牌本来就少 ✓）
   正确的指标是「**在人真的吃了的行里**」填充率 ✓
```

## 验证结果（`--limit 300` 局，16,834 条决策）

```
各列长度一致 ✓
非 chi 行 chipat 全部 = -1 ✓
chi 决策 2,180 条：吃了 184 / 没吃 1,996
吃了的行填充率：**184/184 = 100.0%** ✓
吃了的行分布：{吃法0: 176, 吃法1: 5, 吃法2: 3} ✓（三种吃法都出现 ✓）
```
