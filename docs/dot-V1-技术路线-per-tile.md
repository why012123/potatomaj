# dot V1 技术路线：**per-tile 特征张量 + 一维卷积**（2026-10-21 立）

> 立依据：实测 Mortal v4 权重 —— **1,228,649 参数**、`Conv1d(1012→32) + 2×ResBlock(32) + Conv1d(32→32) + Linear(1088→1024)`，
> 输入 **1012 ≈ 34 牌位 × 每张 ~30 特征**（含历史打牌）。它到天凤 8-9 段。
> 结论：**瓶颈不在参数量，在「特征怎么组织」** ✓ 这条改掉立项书原来的「≥10M 参数」。

## 一、要改什么（一句话）

```
现在：view -> encode() 平铺 645 维全局向量 -> MLP(512,512) -> 9 个头     （看不到"哪张牌在第几巡被打出"）
目标：view -> encode_tile() (34 牌位 × F 特征) -> Conv1d+ResBlock -> FC -> 9 个头 + 价值头
      F 从 20 起（目标 30），通道 64→128，参数目标 **1~3M**
```

## 二、输入规格：`(34, F)` 张量，F = 20（v3.0）

每张牌（34 个位置）各 F 个通道。**全部只用「该玩家看得见的」信息**：

| # | 特征 | 取值 |
|---|---|---|
| 0 | 自己手牌张数 | 0~4 归一 |
| 1 | 自己可见张数（含副露/牌河/宝牌指示/拔北，修 double-count 后的） | 0~4 |
| 2 | 场上剩余张数 = 4 − visible | 0~4 |
| 3 | 是否宝牌 | 0/1 |
| 4 | 是否赤五 | 0/1 |
| 5 | 是否役牌（场风/自风/三元） | 0/1 |
| 6 | 是否幺九 / 字牌 | 0/1 |
| 7 | 自己牌河里这张打过的张数 | 0~4 |
| 8 | 自己最近一次打的是这张（现物自己） | 0/1 |
| 9 | 自己是否振听且这张是自己的听牌张 | 0/1 |
| 10-12 | **三家**各自牌河里这张的张数 | 0~4 ×3 |
| 13-15 | **三家**各自最近一次打的是这张 | 0/1 ×3 |
| 16 | 对已立直家的危险度（复用 `tile_danger`，取最大） | 0~1 |
| 17 | 对任一立直家是现物 | 0/1 |
| 18 | 这张牌是否在**任意**对手副露里 | 0/1 |
| 19 | 这张的「筋」覆盖度（相对立直家牌河） | 0~1 |

全局标量（不进卷积，最后 FC 前 concat，约 20 维）：
`turn, wall_left, hand_size, shanten_onehot(8→取 shanten 值/6), ukeire/40, dora_count, aka_count,
 scores(4)/50000, score_lead, kyoku/7, honba/4, kyotaku/3, hands_left/8, furiten, dealer_repeat, is_dealer, seat/round wind`

> ⚠️ 与现有 645 维的关系：**不复用、不混用** ✓ 新数据用 `encode_tile` 重抽（`tenhou_bc` 加 `--layout v3`）；
> 老 645/560 数据/权重**保持可用**（`feature_dispatch` 已按维度分流，v3 再加一档）。

## 三、网络（PyTorch，4060 上跑）

```
x (B,34,F) --transpose--> (B,F,34)
  Conv1d(F -> C, k=3, pad=1) + BN + ReLU          C=64
  ResBlock(C) x 4   (每个: Conv1d->BN->ReLU->Conv1d->BN + 通道注意力 + 残差)
  Conv1d(C -> C, k=3, pad=1) + BN + ReLU
  flatten (B, C*34)  --concat--> global(20)
  Linear(C*34+20 -> 512) + ReLU
  Linear(512 -> 256) + ReLU
  heads: discard(34) / riichi(2) / call(3) / chi(2) / kan(2) / ron(2) / tsumo(2) / kita(2)
  value: Linear(256 -> 1) + tanh
参数量估算：C=64, 4 blocks -> 约 34*64*512 ≈ 1.11M(FC) + 卷积/块 ≈ 0.2M => **约 1.3M** ✓（与 Mortal 同量级）
```

## 四、执行顺序（谁做什么）

```
① [server, 0.5 天] `aimodel/encode_tile.py`：实现 (34,F) 编码 + 单测（金值、无信息泄漏、形状）
   验收：3 个固定 view 的 sha256 金值；只改新文件，不动现有 encode
② [server, 0.5 天] `aimodel/torch_model.py`：上面的网络 + 与 numpy 版 head 名对齐；参数量自检（1~3M）
③ [server, 0.5 天] `tenhou_bc --layout v3` 重抽 27 批（约 25 分钟，X 变成 34×20 float16 ≈ 1.4KB/行）
④ [server, 0.5 天] BC 2 epoch（4060，约 20~40 分钟）-> 配对赛 vs `mac_rl` / vs pro4v1.2 候选
⑤ [mac] 评审：复核 ①② 的测试与金值、复核 ④ 的配对赛口径（1500 组、Δ/SE/n）
```

## 五、判据（预注册）

```
第一阶段（只换特征+网络，数据不变）：
  ✅ 通过 = vs `maj-pro4v1.1_mac_rl` 的 Δ **> −1.0**（现在的 645 平铺基线约 −1.1）
           且**参数量 1~3M**、训练 2 epoch
  若 Δ 在 −1 ~ +1 之间 -> 记为「打平」，继续加长训练/加数据再判 ✓
  若 Δ < −2 -> 说明卷积结构在这个数据量下不占优，回退，但保留特征（特征本身可与 MLP 组合）✓
第二阶段（数据加量到 5 万局+）：Δ > +3.24（预注册门禁）才算「真强了」
```

## 六、风险

| 风险 | 处理 |
|---|---|
| 34 位置的卷积在 230 万样本上欠拟合 | 先做 C=64/4 blocks（1.3M）；不够再加宽，别一上来 512 通道 |
| 重抽成本（25 分钟） | 可接受；`--layout v3` 与 v2 并存，随时回退 |
| 特征实现错（信息泄漏/顺序错） | 单测钉死：金值 + 「只喂可见信息」的负向验证（把别家手牌改掉，编码必须不变） |
| 与 numpy 训练器不一致 | v3 只走 PyTorch（`torch_model.py`），不要求 numpy 版等价；numpy 版只保留推理对齐图 |
