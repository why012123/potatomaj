## 1) 要隔离的到底是什么

```
【必须保证】「选择最优」的代码路径**在任何情况下都读不到 HOLDOUT 的分数** ✗
```
**为什么不能靠纪律** ✗：
```
· 纪律是「人记得」✓ 而人会忘 ✓ 而且**别人**写的代码不会知道这条纪律 ✓
· 一次手滑（比如把 holdout 的分数也算进 avg ✓）就污染 ✓ 而且**看不出来** ✗
  -> 污染之后的症状是「对 HOLDOUT 也涨」✓ 而那正是我们想观测的信号 ✓
     信号被污染 = 我们**永远不知道有没有过拟合池子** ✗✗
```
**所以目标是：让污染在结构上不可能，而不是在纪律上禁止** ✓

## 2) 三层隔离（**每层都独立可测** ✓ 任一层失效都能被抓到 ✓）

### 第 1 层：**配置层** —— 两个池子在不同的文件里，且 HOLDOUT 有指纹

```
aimodel/pool_select.json     SELECT 池成员（可被选择代码读 ✓）
aimodel/pool_holdout.json    HOLDOUT 池成员（**只被评测入口读** ✗）
aimodel/pool_holdout.sha256  HOLDOUT 列表的 sha256 ✓
```
**「成员不可更换」怎么机械化** ✗：
```
一个测试：算 `pool_holdout.json` 的 sha256，与 `pool_holdout.sha256` 比对 ✓
-> 改成员 -> sha256 变 -> **测试红** ✓
-> 要合法更换 -> 必须**同时改 .sha256 文件** ✓ 而那在 git 里**看得见** ✓
（这就把「悄悄换尺子」变成了「一次显式的、有记录的改动」✓）
```

### 第 2 层：**导入层** —— 选择代码**导入不到** HOLDOUT

```
`aimodel/pool.py`（选择侧唯一入口）
    只读 `pool_select.json` ✓
    **不提供任何读 holdout 的接口** ✗（不是「不调用」✓ 是「没有」✓）

`tools/holdout_eval.py`（评测侧唯一入口）
    独立的脚本 ✓ 读 `pool_holdout.json` ✓ 跑配对赛 ✓ 写 `_data/holdout_log.jsonl` ✓
    **不被任何 `aimodel/` 下的模块导入** ✗
```
**机械检查** ✗：
```
一个测试：
  ① `aimodel/` 下**任何** .py 里都不许出现 `pool_holdout` / `holdout_eval` ✗
  ② `tools/holdout_eval.py` **不导出可被 import 的函数给训练侧用** ✓
     （它可以有函数 ✓ 但训练侧不许 import 它 ✓ -> 由 ① 的同类检查覆盖 ✓）
-> 这条检查是**纯文本的、便宜的、确定性的** ✓ 且**注入一次引用就会红** ✓
```

### 第 3 层：**数据层** —— 选择代码读不到 holdout 的**分数**

```
HOLDOUT 的评测结果只写进 `_data/holdout_log.jsonl`（**append-only 日志** ✓）
选择代码的输入**只有**：
  · SELECT 池的配对赛结果 ✓
  · RL 自身的训练统计 ✓
-> **没有第三个来源** ✓
```
**机械检查** ✗：
```
一个测试：选择函数（`cmd_rl` 里那段）的**入参里不许出现** holdout 相关名字 ✓
（同 ①，用文本检查即可 ✓）
```

## 3) ⚠️ 我承认这个设计有一个洞（**写出来，不藏**）

```
第 2/3 层都是**文本检查**（grep `aimodel/` 下有没有 `holdout` 字样 ✓）
弱点 ✗：
  · 可以**绕开**：把 holdout 的分数**先写进一个中转文件** ✓
    再让选择代码读那个中转文件 ✓ -> 文本检查**抓不到** ✗
  · 也可以动态绕：`getattr(__import__("tools.holdout_eval"), ...)` ✗
```
**为什么我还建议先上这三层** ✓：
```
· 它挡住的是**手滑**（占真实风险的绝大多数 ✓）✗ 不是**刻意绕开** ✓
· 而且**刻意的绕开**不是我们要防的威胁模型 ✓
  （这里没有对手 ✗ 只有「未来的自己忘了」和「另一个 agent 不知道」✓）
-> 但**我必须说清它的边界** ✗ 免得它被当成「绝对隔离」✓
```
**若你要更强的**，可加第 4 层（我列出但**不建议现在做** ✗ 因为成本/收益比差 ✓）：
```
第 4 层：**进程级隔离** ✗
  holdout 评测跑在**另一个进程**里 ✓ 结果写文件 ✓ 选择进程**没有读该文件的权限** ✓
  用文件 ACL 或不同用户实现 ✓
  -> 真的不可能读 ✓ 但要处理跨平台 ACL ✓ 成本高 ✓
```
