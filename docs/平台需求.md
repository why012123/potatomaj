## 一句话

网页版日本麻将对战平台：多人在线、各自开房、选 AI 当对手或看 AI 互打，
同时**每一局都在为模型训练积累数据**。

## 一、边界

| | |
|---|---|
| 你的目录 | **`webapp/`**（前端 + 服务端）+ 仓库根的 `run.py` |
| 共享只读 | `aimodel/sanma.py`、`engine.py`、`variants.py`、`agents.py`、`net.py`、`potatomaj/tiles.py` |
| **不要动** | `aimodel/train*.py`、`rewards.py`、`encode.py`、`net.py`、`weights/`（训练侧的地盘） |
| 允许 | `engine.py` 里**只加不改**观战/前端用的钩子（见第四节），规则逻辑一个字不许动 |

**判断规则层有没有被改坏**：`python aimodel/tests/run_all.py` 必须 17 套全绿。

## 二、技术架构

- **WebSocket 为主**（实时推送），HTTP 只用于静态资源 / 房间列表 / 登录
- **服务端权威**：客户端只发「我要打这张」这种意图 ✓ 服务端校验合法性后再广播 ✗
  **绝不信任客户端发来的状态**
- 每个房间一个独立的 `Game` 实例 + 独立事件循环，**房间之间零共享可变状态**
- **AI 推理不能阻塞事件循环**：放线程池 / 进程池，或每个 AI 座位一个 worker
- 前端用现成牌面图：`potatomaj/templates/*.png`（命名 `1m..9m / 0m / 1p.. / 1s.. / 1z..7z`）
  现有 `aimodel/ui/server.py` 有 `/tiles/<id>.png` 的实现可以参考
- **不要用 Electron**（这是网页）

### 和 aimodel 的接口

```python
from aimodel import variants
from aimodel.agents import MLAgent, HeuristicAgent
from aimodel.net import Net

spec = variants.get("maj-flashv1.2")      # 支持别名，自动指向最新版
net = Net.load(spec.path)
agent = MLAgent(net, seed=123, greedy=True)
# agent.decide(decision, view) -> int（选项下标；引擎已在 action_mask 里限好范围）
```

**模型会持续更新**（v1.3、v1.4 陆续训出来）：
- 模型列表要**动态扫描 `aimodel/weights/`**，不要写死
- 新模型放进去就能在界面上选到，不用改代码、不用重启

**⚠️ 存量权重的现状**：44 个权重都**缺 `chi` 决策头** ✗
加载时会发 `UserWarning`、把该头零初始化、记进 `net.untrained_heads` ✓
**那些决策走启发式兜底，模型不会崩** ✓
→ 平台侧要做：启动时调 `variants.audit_weights()` 把结果写进日志；
界面上**标注**这些模型（例如「该版本未训练吃牌」）✓

## 三、会话隔离（硬性）

1. **房间制**：创建房间 → 房间号/邀请链接 → 别人加入或观战
2. **状态隔离**：房间 A 的任何数据不允许出现在房间 B 的 WebSocket 消息里
3. **座位视角**：每个连接只收自己座位的信息 ✓
   **别人的手牌在协议层就不下发** ✗ —— 前端藏牌等于没藏
4. **断线重连**：掉线后重连要能恢复到当前局面（含「轮到你出牌，等你 30 秒」）
5. **超时兜底**：思考超时自动打一张 / 交给 AI 托管，不能把整桌卡死
6. **多人**：至少 10 房间 / 40 连接同时在线，压测脚本一起交
7. **观战全亮牌只在纯 AI 房生效**：桌上有任何真人座位时，后端必须拒绝

## 四、UI：天凤式真实牌桌

**布局**（日本麻将行业惯例，别自己发明）：
- **自己永远在下方**，其余逆时针：下家→右、对家→上、上家→左
- **牌河**：每行 6 张、最多 3 行，从靠近自己的一侧往外排；
  **立直宣言牌横放 90°**（最重要的视觉信号，不能省）
- **副露**摆在自己手牌右侧（其它家按朝向旋转）；**暗杠中间两张扣过来**
- **手牌**贴自己那一侧的下边缘，**刚摸的那张留一道缝**
- **中央信息区**：剩余张数、场风、第几局、亲家、宝牌指示、立直棒数、
  当前行动者（高亮 + 倒计时）
- 别家手牌画牌背，张数要对；名牌上有名字/点数/自风/亲家标记/立直标记/拔北数
- 出牌、鸣牌**要有动画**（150~250ms 缓动，不要瞬移）
- 配色走真实麻将桌：深绿绒布 + 木色边框 + 牌有阴影
- **响应式**：1366×768 到 2560 宽都不能错位

**交互**：
- 轮到自己时点手牌出牌、点按钮鸣牌/立直/拔北/荣和/自摸，也支持数字键
- 可选动作**只能从服务端下发的列表里选**，前端不要自己判断合法性
- 结算页：完整牌型（含和牌张单独标出）+ 役种列表（真役/宝牌分两组）
  + 番符 + 点数收支（放铳者标红、和牌者标金）

**引擎侧要加的钩子**（只加不改，规则逻辑一个字不许动）：
- `Game.on_ui` 回调 / `Game.pump()` / `emit_pending_hand_end()` —— 给前端推结构化观测
- `Player.pond_red` —— 牌河里赤 5 的标记（前端要画红的）
- 这些**不参与任何规则判定**，和已有的 `Game.on_action`（结构化动作流）并存 ✓

## 五、AI 对战 / 观战

- 可选：纯真人房 / 人 + AI 混合 / 纯 AI 观战房
- 选 AI 时能挑**具体模型和版本**（`maj-flashv1.2`），界面显示中文风格标签
  （标准/防守/速攻/大牌）
- AI 每手有可调节节拍（0~3 秒），不然观战看不清
- **AI 异常必须降级成内置教师**并在界面标注，绝不能让整桌崩掉

## 六、★ 决定级数据记录（第一版就要有）

**这一节是平台的战略价值所在 —— 它产出的数据会用来训练模型。**

### 每个决策点记一条

```
局面快照：自己的手牌、四家牌河、副露、宝牌指示、立直状态、巡目、点数、风、剩余张数
可选动作：引擎给的全部合法动作（原样存，不要加工）
实际选择：玩家选了什么
思考用时：从轮到该玩家到决定，毫秒
```

**只有决策级数据能训练** ✗ 「谁第几名、多少点」这种只有结果的没用 ✓
**AI 之间的对局同样要记。**

### 每条带上玩家画像

```
玩家 ID（匿名，同一人跨局要能归到一起）
该玩家当前累计：已打局数 / 平均顺位 / 一位率 / 放铳率 / 和了率
自报段位 + 主玩模式（三麻/四麻）
该玩家在平台内的 ELO
```

**ELO 必须和 AI 用完全同一套公式** ✓ —— 这样人类分数和模型分数在同一量纲上 ✓
「打赢了 `maj-flashv1.1`」本身就是一个校准过的水平读数 ✓

### 全信息落盘

一局结束时把**四家手牌 + 和牌详情**（役种/番/符/收支）一起存 ✓
—— 这是危险度模型的正样本来源 ✓
（数据侧已验证这条路的回报：selfplay 数据把「没人立直却仍送和」这一片的
AUC 从 0.8130 提到 **0.8986** ✓）

### 不要在收集时筛选

全量记录，**弱玩家的数据一条都不要丢** ✓ 筛选标准放训练时定 ✓
（筛选是不可逆的 —— 现在觉得没用，半年后可能正好需要）

### 存储与工程

- 按天分文件的 JSONL，一行一条决策，不要塞数据库
- **写完压缩**（zstd 或 gzip）—— 决策级数据涨得很快
- **异步写、失败只打日志**：记录绝不能影响对局
- 落盘目录要有容量上限和轮转策略
- 提供导出工具：`python tools/dump_games.py --since 2024-01-01 --out x.jsonl`

### 隐私与告知

- 开局界面写明：「本局对局数据会被记录，用于模型训练」
- 玩家可选「不记录本局」，选了就真的不记
- 不要对外展示带玩家 ID 的原始日志
- 玩家 ID 用随机生成的匿名串，不要用邮箱/手机号/昵称

## 七、★ 评测面板

首页要有公开可看的战绩面板：

```
人类 vs 各模型：对局数 / 人类胜率 / 人类平均顺位 / 模型放铳率
各模型在人类对局中的表现排行
平台内 ELO 排行榜（人类 + 模型混排）
```

**为什么**：ELO 是「模型之间谁强」，**人类胜率才是「这东西好不好用」** ✓
这个面板既是给玩家看的，也是这个项目对外最有说服力的指标 ✓

## 九、验收标准（每条都要跑过并贴输出）

1. `python aimodel/tests/run_all.py` **17 套**全绿
2. **隔离测试**：两个房间打不同牌局，断言 A 房消息里不出现 B 房任何一张牌
3. **作弊测试**：以玩家身份连接，断言收到的 JSON 里**没有别家的手牌**
4. **AI 合法性**：AI 自对弈 200 局，引擎零异常、零非法动作、牌数守恒（136/108）
5. **并发压测**：10 房间 × 4 人同时跑，无串局
6. **断线重连**：中途 kill 掉一个客户端，重连后局面一致
7. **数据记录**：打一局真人 + 三个 AI，导出完整决策级 JSONL；
   把落盘目录设成只读，对局仍正常（记录失败不影响游戏）
8. **同一玩家打 10 局**，数据能通过 ID 串起来，累计统计正确
9. 截图：四麻/三麻牌桌、结算页、观战页、房间列表、评测面板
   （各 1366×768 和 1920×1080）

## 十、部署与运维

- 服务器：i9-14900HX / 24 核 / 32GB，**但机器同时在跑训练和数据生成**
  ⚠️ 数据生成实测会吃很多内存（`workers × matches × 3MB`，16×2500 能把 32GB 打爆）
  → 你的服务要限制自己的 CPU/内存占用
- 一键启停脚本 + systemd service（开机自启、崩溃重启）
- 公网访问写清 nginx 反代 + TLS，以及**至少一个轻量身份识别**（昵称+房间密码也行）
- 日志写文件并轮转，不要只打 stdout

### ⚠️ 这台机器的两个坑

1. **会话里启动的长进程会被清理** ✗（实测 15 秒~3.5 分钟静默消失）
   → 长任务交子智能体，或拆成短进程循环 ✓
2. **杀进程别按 `*selfplay*` 匹配** ✗（multiprocessing 子进程命令行里没有这个词）
   → 按 `*multiprocessing-fork*` 匹配，否则会留一地孤儿继续吃内存 ✓

## 十一、协作纪律（都是踩出来的）

- **动 git 之前先跑 `bash tools/safe_git_sync.sh`** ✗
  它会列出「未提交的改动 / 你有而上游没有的文件 / 未跟踪文件 / stash」
  —— **未跟踪文件就是这次被清掉的那批** ✓
- **写完就提交** ✗ 2000 行留在工作区 = 随时归零 ✓
- **三个会话共用一个工作树很危险** ✗ 用 `bash tools/setup_worktrees.sh` 各开一个目录 ✓
- **提交信息里写清你动了哪些目录** ✓ 别人 `fetch` 一下就知道要不要停手 ✓
- 长任务别在主会话跑 ✓
