# 对手池设计（v1 提案）

> server · 2026-10-16 · 状态：**待 mac 批** · 未动代码

## 0) 一句话

给 RL 一个「**会还手、且不重复**」的对手集合 ✓
并用**留出对手**把「选出来的强」和「真的强」分开 ✗

---

## 1) 为什么现在必须做（不是「顺便优化一下」）

```
现状：RL 只跟自己打 ✗
后果（早已知道）：**自打自学不到新东西** ✓
  模型 A 跟模型 A 打 -> 双方的策略分布相同 ✓
  -> 赢的那一方只是**这一次的运气/先手** ✓ 不含可学的新信息 ✓
【通则一】再确认一遍 ✗：
  判据若选「**像谁**」✗ 永远赢不了那个「谁」✓
  -> 只跟自己打 = 判据只选「像我」✗ -> 天花板就是我 ✓
```
**所以对手池不是提速 ✗ 是抬天花板 ✓**（数据侧 12% 是速度 ✓ 这是质量 ✓）

---

## 2) 池子的四个来源（**必须异构**）

```
① **风格对手**（现成 ✓ `aimodel/variants.py` 的 same_players ✓）
   不同 reward 训练出来的模型 -> 打法本就分岔 ✓ 天然异构 ✓
② **历史快照**（selfplay 里已有 snapshot ✓ 但只有一个 ✗ -> 要多代）
   同一个模型的不同代 -> 提供「渐进难度」✓ 且**不会太难** ✓
③ **教师**（teacher ✓ 现成 ✓）
   BC 的来源 ✓ 它是最稳的底线对手 ✓
④ **人类数据模型**（`_mac_2ep` 那一族 ✓）
   **三杠杆排序已证：换成人标签 +9.214** ✓ -> 它是最有价值的一类对手 ✓
```
**⚠️ 为什么强调「异构」** ✗：
```
同构的池子 = 一张牌桌坐 4 个自己 ✗ -> 等价于自对弈 ✓ 白搭 ✓
异构度不足 -> 学到的只是「怎么打自己」✗（过拟合池子 ✓ 留出对手就是查这个 ✓）
```

---

## 3) ⭐ 留出对手（**本设计的核心，也是我最想请你审的一条**）

```
定义：**从不参与任何选择决策**的对手 ✗
      它们的唯一用途 = 最终评测 ✓
```
**要防的是什么** ✗：
```
若选择只用池内对手 ✓ 模型会**朝池子过拟合**✗
  表现：对池内胜率涨 ✗ 对池外不涨甚至跌 ✓
  -> 这正是【通则一】的变体：判据选「打赢这个池子」✗ 不等于「变强」✓
```
**具体做法**：
```
池子分两份（**互斥** ✓ 一次分配、全程不变 ✗）：
  SELECT 池（约 70%）-> 允许用于「选最优」✓
  HOLDOUT 池（约 30%）-> **只在里程碑评测时用** ✗ 绝不进任何选择循环 ✓
      且 **HOLDOUT 的主力是「人类数据模型」+「教师」** ✓
      （因为「换标签 +9.2」已证它们信息量最大 ✓）
```
**⚠️ 三个必须写死的纪律** ✗：
```
① HOLDOUT 的成员**不可更换** ✗（换成员 = 换了尺子 ✓ 历史数字全不可比 ✓）
   若要换 -> 新开一个 HOLDOUT-2 ✓ 两把尺子并行一段时间 ✓
② 选择决策**不许看 HOLDOUT 的数字** ✗
   实现上：HOLDOUT 的评测**只在日志里落盘** ✓ 不喂给任何「选最优」的代码路径 ✓
   （只靠纪律不够 ✗ 要靠**代码路径隔离** ✓ 否则一次手滑就污染 ✓）
③ 里程碑评测的**判据与选择判据必须不同** ✗
   选择：对 SELECT 池的**配对赛** ✓
   评测：对 HOLDOUT 的**配对赛 + SPRT** ✓（同牌山 ✓ 同协议 ✓）
```

---

## 4) 选择判据（**这里最容易犯我们犯过三次的错**）

```
【必须】配对赛（同牌山 ✓ 消除发牌方差 ✓）✗ 不是内部评测 ✗
【必须】先算 MDE，再决定要不要看那个「新高」✗

已实测的两个数（可直接用 ✓）：
  内部评测（80 场/轮，取 20 次噪声的最大值）报告 **+11.3** ✗
  可信配对赛                                        **+1.89** ✓
  -> **内部评测夸大 6 倍** ✗
  真实每轮增益 ≈ **+0.09** ✓
  MDE +2 需要 224 s ✓ -> 要检 +0.09 需要约 **30 小时** ✗
```
**⭐ 所以本设计里最重要的一条建议** ✗：
```
**不要用「每轮新高」来选最优** ✗ —— 每轮增益 +0.09 << MDE +2 ✓ 那是选噪声 ✓
改用：**每 K 轮（如 K=10）做一次配对赛** ✓ 且只在
      **预期累积增益 > MDE** 时才做选择 ✓
   K=10 -> 预期 +0.9，仍 < 2 ✗ -> K 至少要 **25** 才有 +2.25 > MDE ✓
   -> 建议 **K = 25**（即一轮「代」= 25 个 RL iter ✓）✓
   这样一夜能跑约 1 代 ✓ 但**每代的选择是可信的** ✓
（宁可少选几次 ✓ 也不要选噪声 ✗ —— 这是我们花了整晚学到的 ✓）
```

## 5) 池子的动态维护

```
【渐进难度】每次选择后，把**当前最优**加进 SELECT 池 ✓
  原因：旧对手会变弱 ✓ 池子若不更新 -> 模型「打旧对手很熟」✗ 学不到新东西 ✓
【容量】SELECT 池保留最近 N 代 + 全部风格对手 ✓
  建议 N = 5 ✓（太多 -> 平均太弱 ✓ 太少 -> 过拟合最近 ✓）
【退役】不再增长的老对手从 SELECT 退役 ✓
  **但它们进 HOLDOUT** ✗ —— 作为「历史基线」✓ 用来检测「是不是退步了」✓
  （这是唯一允许的「从 SELECT 移到 HOLDOUT」✗ 因为 HOLDOUT 只增不减 ✓）
```

## 6) 验收（**怎么知道对手池真的有用**）

```
主判据：对 **HOLDOUT 池** 的配对赛（同牌山 + SPRT ✓ 与三杠杆排序同协议 ✓）
对照：**同起点、同预算、无对手池**（= 纯自对弈 ✓）的那一组 ✓
判据：`有池 vs 无池` 的 **Δ 段位分** 与 **p 值** ✓
+ MDE 检查：先说清这个对照的 MDE 是多少 ✓（按上面 K=25 估 ✓）
```
**⚠️ 而且要预设**「**若 Δ 不显著**」**怎么办** ✗：
```
不显著 -> 不许说「对手池有用」✗ 也不许说「没用」✗
       -> 报告 MDE ✓ 并说明「本预算下检不出 <X 的效果」✓
（这是我们三次踩过的坑：**不说清 MDE 就没法解释不显著** ✓）
```
