## 四、度量方法论（本轮最重要的产出，比任何单个数字都值钱）

1. **`arena_test` 是确定性的**（同牌山）——它给的 `SE` 只是**评估精度**，
   **不含训练随机性** ✗。确定性评估会给出一个**精确但有偏**的数，
   反而让人**高估**实验可靠度。
2. 因此比较两个**训练配置**：
   - 每个配置 **≥3~4 个种子**，报 **mean ± SD**（不是单个 Δ）
   - 判据（预注册）：两配置 mean 之差 **> 2 × 合并 SD** 才算「有差异」
   - 检出 `Δ=4` 且满足该判据所需的种子数：`2.5·√(2/N) < 2` -> **N ≥ 4**
3. 报 Δ 时必须注明：「**两个训练的比较**」还是「同一个训练的两次评估」。
4. 报模型时必须给 **sha256**（文件名相同 ≠ 内容相同）。

## 七、本轮踩过的坑（按踩到的顺序）

1. **对照不干净 ×3**：batch / seed / 代码版本，各自都足以吃掉 ±4 分 → 见第三节
2. **用「远端引用」代表「在跑的代码」**：`git show origin/webapp:…` 推「平台选不到」✗
   → 被 server 的 `GET /api/models` 与那一局的实际记录推翻
3. **把「两个 Δ 差不多」当结论**：两种抽法同时改了两个变量（样本数与独立局数）
4. **用错计量单位**：按行抽 25% ≠ 少 1/4 的局（4 万局全都还在）
5. **权值平均**：同初始化种子也不够
6. **`--log` 默认路径覆盖仓库文件**：`aimodel/weights/train_log.json` 被覆盖过一次（已恢复）
7. **macOS `seq 1 0` 输出 `"1 0"`**：我的「不训练冒烟测试」真的启动了一整块训练
8. **commit message 里的反引号被 shell 执行**：消息被吃掉 → 改用 `-F <file>`

## 八、平台侧已知偏差（**线上表现 ≠ 我们的配对赛数字**）

这一节列的是「**为什么用户在平台上感觉到的强度，和我们测出来的不一样**」。
四条都是实测的，不是推测。

| # | 偏差 | 方向 | 证据 / 处置 |
|---|---|---|---|
| 1 | **名册是客户端的**，服务端没有存法 | 🔴 **影响最大** | 两次实测 `GET /api/rooms`：AI = `teacher` / `flash4v1.1` / `flash4v1.2` / `huge4v1`，**`mac_rl` 从未上座**。→ **必须在界面里手动把至少一个座位选成「四麻·标准」**，server 和 mac 都改不了 |
| 2 | **WIP 的「逐吃法选项」让 AI 静默不吃牌** | 🔴 线上更弱 | 实测：选项 `['pass','chi']` 时 head=1 → 正确；选项 `['pass','chi:10:12',…]` 时 head=1 → **静默变 0 = pass**（不报错、不警告）。`main` 不受影响 ✓（所以**全部配对赛数字不需要重算**），但**平台跑的是 WIP** → 平台上的四麻模型一直没在吃牌。已修，待并入 |
| 3 | **chi 是二值头**：吃不吃由模型定，**吃哪一种由引擎按向听挑** | ⚠️ 已知天花板 | `main` 里 `ACTION_TABLE["chi"] = ("pass","chi")` → 「吃牌的最终形态」有一半来自启发式，不是学出来的。这限制了四麻模型的上限 |
| 4 | **teacher 代打有独立标记** ✓ | ✅ 不污染 | 落盘 `source=teacher_no_head` / `kind_player=ai` / `player=ai:…` → 教师回合可按 `source` 过滤掉。空房 `empty_room_ttl=1800s`（30 分钟）自动收桌 |
